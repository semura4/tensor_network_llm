## 0. 要約（30秒）

- Blueqat の半導体量子コンピュータは、**産総研（AIST）のシリコンスピン量子ビット**
  を基盤とする「Open Silicon Quantum」プロジェクトで、**cryo-CMOS / QSoC（量子ビット
  と制御回路を1チップ統合）** を看板に、2026 年の商用機投入を掲げている。
- 産総研系のシリコンスピン量子ビットは一般に **単一電子スピン（Loss–DiVincenzo 型）
  + ゲート電場/マイクロ波（ESR/EDSR）+ マイクロ磁石** 方式。これは我々のツールキット
  が前提とする **exchange-only（EO, 3ドット=1論理量子ビット）とは符号化が異なる**。
- したがって **我々の EO ゲート合成層はそのままは載らない**。これは正直に認める。
- 一方で **(a) cryo-CMOS / QSoC 制御メモリのモデル化、(b) 交換相互作用ベースの2量子
  ビットゲート（CZ）の電荷雑音校正とロバスト設計、(c) バレー漏れの物理とバレーロバ
  ストパルス、(d) 回路→ネイティブゲート→パルス→コントローラメモリの中間層アーキ
  テクチャ** の4層は、単一スピン方式にも高い価値で転用できる。
- 最も適合度が高いのは **(a) cryo-CMOS / QSoC** — Blueqat の看板そのものだから。

**符号化方式の確度について（重要）:** 産総研のシリコンスピン量子ビットは公開資料で
は「微小量子ドットに電子1個を閉じ込め、ゲート電場/マイクロ波（ESR/EDSR）+ マイクロ
磁石で操作」と説明されており、**単一電子スピン方式と見るのが自然**。ただし Blueqat
チップの符号化が単一スピンで確定、と断言できる一次情報までは取れていない。本メモは
**「単一スピン主軸」を前提に置きつつ、EO の場合も成り立つよう書く**。

**動作温度について（重要）:** Blueqat は「1–3K で動く＝冷却が安い」を売りにしている
が、高忠実度の動作に**本当に必要な温度は ~0.3K（サブK）**という見方が現実的（熱励起
バレー占有・読み出し SNR・コヒーレンスの要請）。「ホット量子ビット」は楽観シナリオ。
この差は #1 のスタディの結論を支配する（下記 §4 #1：サブK では冷却電力が配線より遥か
手前の律速になる）。冷凍機の冷却能力は ~T² で効くため、4K と 0.3K では予算が ~100×
違う。

## 2. 率直な前提整理 — 何が直接は載らないか

我々のツールキット（`eo_pulse_ir`）の中核は **exchange-only 符号化** に最適化されて
いる:

- 3 ドット = 1 論理量子ビット（S=1/2 DFS ダブレット）
- すべてのゲートを **交換相互作用のみ**で合成（単一量子ビットゲートも 3 ドット内交換、
  CNOT は 34 パルスの交換列）
- バレー位相差による交換抑制 J_eff = J·cos²(Δφ/2) を漏れ源として扱う

単一スピン方式では:

- 1 ドット = 1 量子ビット
- 単一量子ビットゲートは **マイクロ波 ESR/EDSR**（交換ではない）
- 2 量子ビットゲートは **交換相互作用（CZ / CPHASE / √SWAP）**

→ **単一量子ビットゲートの合成（我々の H/X/Y/Rz 交換列）と、3ドット EO 符号化、
バレー位相による交換抑制モデルは、単一スピン方式には直接は転用できない。**
ここを誇張しないことが、提案の信頼性の前提になる。

## 3. それでも高価値で転用できる層（適合度順）

### (a) cryo-CMOS / QSoC 制御メモリのモデル化 — **適合度：最高**

Blueqat の看板がまさに cryo-CMOS / QSoC。我々は既に **HRL 流の cryo-CMOS 命令メモリ /
パターンメモリモデル**を持っている（`HardwareConfig`、`eo_pulse_ir` のコントローラ層）:

- `J(V) = j0·exp((V−v0)/vc)` から DAC コードを生成
- 命令メモリ語数 / シーケンサ数 / 出力あたりパターン語数の予算化
- 任意の `(edge, area)` パルス列に対し、コントローラメモリのフットプリントを自動算出

**符号化に依存しない。** 単一スピンの CZ パルス列・EDSR パルス列を入力すれば、その
まま「この量子ビット数・このゲートセットだと制御メモリが何語必要か」「室温エレキから
cryo-CMOS に移すと配線・メモリがどう効くか」を定量化できる。これは Blueqat の
「2027–28 に配線限界 → cryo-CMOS」というロードマップに直接刺さる。

> 我々が作れるもの: 単一スピン Si 量子ビット N 個（EDSR 1Q + 交換 CZ）のゲートセット
> に対する **QSoC 制御メモリ予算スタディ**。室温エレキ併用 vs cryo-CMOS 統合での
> メモリ/配線/帯域のスケーリングを N について出す。

### (b) 交換ベース2量子ビットゲート（CZ）の電荷雑音校正＋ロバスト設計 — **適合度：高**

単一スピン方式でも **2量子ビットゲートは交換相互作用**で行う。ここは我々の物理が
そのまま効く領域:

- 交換プロパゲータ（厳密閉形式 `exp(-i A S_i·S_j)`）
- 電荷雑音モデル `a_eff = a·(1+ε), ε~N(0,σ)`（dJ/J）と、実測 RB から σ を合わせる
  校正ループ
- アンサンブル平均忠実度を最大化するロバスト最適制御（解析勾配 GRAPE）

EO 用に作ったロバスト設計エンジンは、ターゲットを CNOT から **CZ/CPHASE** に差し替え
れば単一スピンの2量子ビットゲートに転用できる（合成アンサッツは EO 特有だが、交換
ハミルトニアン・雑音モデル・最適化器は共通）。

> 我々が作れるもの: 単一スピン **交換 CZ ゲート**の電荷雑音（dJ/J）に対するロバスト
> パルス設計と、「ナイーブ CZ vs ロバスト CZ」の忠実度比較（既存の `eo_robust_compare`
> の CZ 版）。

### (c) バレー漏れの物理とバレーロバストパルス — **適合度：高（シリコン普遍）**

バレー分裂・バレー漏れは **シリコン量子ビット共通の課題**で、単一スピンでも効く
（バレー依存 g 因子、バレー励起状態への漏れ、バレー分裂の素子間ばらつき=歩留まり
ボトルネック）。我々は spin⊗valley の4準位モデルと、バレー位相広がりに対するロバスト
設計を持つ。

我々の検証可能な結果 — **「ロバストゲートがバレー軸で charge-noise-free 上限すら超える」**
— は、符号化に依らず「バレー均一性こそスケーリングの律速」というコンセンサスを突いて
いる。さらに今セッションで作った **リーケージ蓄積判定実験**（`eo_leakage_accumulation`）
で「バレー漏れの蓄積は sub-diffusive（コヒーレントな n² ではない）→ measurement+reset
が主対策、パルスで L₁ を下げるのが最重要」と定量化済み。これは QEC サイクルを回す
ハード屋に直接効く知見。

> 我々が作れるもの: 単一スピン Si における **バレー漏れスタディ**（交換 CZ 中のバレー
> 漏れ、E_VS/J 比に対する閾値、reset 周期の見積り）。

### (d) 回路→パルス→コントローラメモリの中間層アーキテクチャ — **適合度：中〜高**

「論理回路 → ネイティブゲート → パルススケジュール → コントローラメモリ」という
**中間層 IR の設計思想そのもの**は符号化に依らない。差し替えるのはゲート合成テンプレ
ート（EO 交換列 → 単一スピン EDSR + 交換 CZ）だけ。スケジューラ（ドット可用性 ASAP）、
コスト指標、メモリモデル、可視化、外部最適化器/eoqrid アダプタの seam はそのまま動く。

> 我々が作れるもの: 単一スピン向けゲートライブラリ（`gate_library` seam に EDSR 1Q +
> 交換 CZ を流し込む）。IR 仕様 v0.3 の `gate_library` 機構は既にこの差し替えを想定
> した設計になっている。

### #1 実装結果（`eo_pulse_ir/singlespin.py`, `scripts/eo_qsoc_budget.py`）

単一スピン Si アレイ（1ドット=1量子ビット、EDSR 1Q、ベースバンド交換 CZ）の制御プレ
ーン予算を N の関数で算出。CZ チャネルは既存の `J(V)=j0·exp((V−v0)/vc)` DAC モデルと
パターン/命令メモリ抽象をそのまま流用し、`build_memory` と整合することをクロスチェック
で確認（同一 CZ は出力あたり1パターン語に重複排除される）。

**最重要の知見（温度が律速）:** 高忠実度のスピン量子ビットに本当に必要なのは
**~0.3K（サブK）** であって、1–4K の「ホット量子ビット」領域ではない。希釈冷凍機の冷却
能力は ~T² で効く（~1 mW @ 100 mK）ので、0.3K では予算は **~9 mW** しかない。一方
**今日の cryo-CMOS は 1 チャネルあたり ~9–10 mW** 消費する。したがって制御を量子ビット
と同じ 0.3K に同居させると、**配線が効くより遥か手前で熱的に頭打ち**になる:

| 1量子ビットあたり冷却電力 | 0.3K での最大量子ビット数 | 備考 |
|---:|---:|---|
| 10 mW | ~0 | 今日のフル cryo-CMOS コントローラ |
| 1 mW | **8** | 近未来目標 |
| 100 µW | 89 | 攻めた値 |
| 1 µW | 9k | 研究目標 |
| 10 nW | 900k | 熱/Landauer 下限近傍 |

→ **1M 量子ビットを 0.3K で動かすには ~9 nW/量子ビット**（今日比 ~10⁵–10⁶× の削減）が
必要。これがドミナントな壁で、**配線（室温電子機器で N≈128、クロスバーで N≈4.1k）は
二次的**。結論: cryo-CMOS は「配線問題を**冷却電力問題に変換する**」のであって、配線を
解いても 0.3K の熱予算という、より厳しい壁が残る。

**QSoC プリミティブはまさにこの冷却電力を狙い撃つ:**
- 波形を冷却側に常駐・局所再生 → 300K↔冷却の往来は読み出しビット列だけ（サンプル
  ストリームより桁違いに小）、配線数は共有デジタルバスで N に対し一定。
- **冷却側波形バンクは N に対して一定**（全量子ビットが同一ゲート形状を共有＝既存
  `build_memory` の重複排除と同じ原理）。共有・低デューティ比の再生で**冷却側の動的
  電力を最小化**する — 熱の壁が要求するレバーそのもの。
- アーキテクチャの分岐: ①制御を 0.3K で超低電力動作させる（nW級が必要）か、②制御を
  4K（~1W 予算）に分離し 0.3K↔4K の配線・熱流入コストを払うか。これが本質的な選択。

成果物: `out/qsoc_budget/`（`qsoc_lines.svg`, `qsoc_bandwidth.svg`,
`qsoc_cold_memory.svg`, `qsoc_cold_power.svg`, `report.md`, `results.json`）。予算モデル
は標準ライブラリのみ（numpy は SVG 描画にのみ使用）。温度・冷却予算・1量子ビットあたり
電力を含む全パラメータは `SingleSpinControl` / `Workload` で可変 — 実測デバイス値を入れ
て特化できる。

## 6. 正直なリスク・限界

- **符号化の不確実性。** Blueqat チップが単一スピンで確定、という一次情報は未取得。
  本メモは単一スピン主軸を仮定。EO 採用なら既存ツールキットがほぼそのまま載るため、
  むしろ好都合（その場合は確認の上、既存 whitepaper をそのまま使える）。
- **EO ゲート合成は転用不可。** 1Q EDSR と単一スピン符号化は別物。誇張しない。
- **我々の強みは「物理に裏打ちされた制御中間層」であって素子・冷却・配線そのもの
  ではない。** ハード本体は産総研の領分。我々が刺さるのは制御・コンパイル・校正・
  メモリ予算という中間層。
